# Bovary execution architecture

The `bovary` package contains the execution implementation. `bovary.contract` defines Request, Event, Result and typed ExecutionError. Imports construct no model, GPU backend or telemetry. `runtime.create_workbench()` supplies the same `routing.Workbench.execute()` to CLI, GUI and evaluations. Benchmark launchers also support a separate one-shot measurement path.

The local adapter owns a single child and a shared `work/benchmark.lock` for its full loaded lifetime. CPU and CUDA binaries are separate. CPU requests strip streaming/plugin environment variables, set zero GPU layers/cache, and require the native CPU-only build before backend initialization. Selecting a GPU profile explicitly grants GPU permission; it cannot happen as a fallback.

The native executable identifies its protocol as `bovary-worker 2`. The `--worker` protocol is bounded stdin/stdout framing, with no network listener. `RUN <output tokens> <UTF-8 byte count>\n` is followed by exactly that many prompt bytes, limited to 1 MiB. Frames are `<kind> <byte count>\n<payload>`: R ready, T text bytes, D JSON metrics, E typed JSON error. QUIT or stdin EOF unloads. One request is active at a time. Every request constructs and frees a separate context and batch; the model stays loaded, so independent requests share weights but no KV/conversation state. Configuration changes reload. Actual tokenization enforces context limits before processing.

In protocol 2, `RUN 0 <UTF-8 byte count>` denotes a local request without an explicit output cap. The adapter accepts this only for `Request.output_tokens=None` with a future deadline and no escalation. Positive RUN limits retain the numeric cap (128 by default); zero is an internal protocol sentinel, not a CLI token value. Tokenization derives a finite context-dependent generation limit before generation. D metrics report `generation_limit` and `finish_reason` (`eos`, `token_limit` or `context_limit`); the adapter checks those values against the request, actual prompt/context use and emitted frames. Model end permits normal completion; exhausted numeric/context limits return `truncated`. Runtime validators do not grade a truncated result, and it cannot trigger escalation. Frame and total-output bounds remain finite and are checked against the request/context and final usage metadata.

Cancellation/deadline stops and waits for the owned child. A later request starts a fresh worker. A Windows Job Object with KILL_ON_JOB_CLOSE handles abrupt parent death; normal idle exit also closes stdin. Backpressure/frame/diagnostic bounds limit buffering. CPU runs create no GPU sampler. The selected local profile controls numerical settings, expert selection and streaming safeguards.

The pinned upstream server is a separate tool stack, disabled in this project's build. The selected integration extends the already verified root CLI with a small protocol and shared request routine, preserving its placement, prompt and numerical settings. This does not claim that the upstream server is incompatible; it avoids enabling a second configuration/execution stack before its streaming behavior is verified.

Routing calls the canonical offline planner. Manual choice may run an unqualified configuration; Suggest performs no inference. Validators compare application expectations and can request review. At most one explicit escalation follows a failed local validator and rechecks privacy, allowed destinations, deadline and provider budget. Infrastructure failures and truncation remain failed/review outcomes rather than silent fallback.

The commercial adapter requires an explicit positive output cap and rejects no-cap requests. It has a fixed HTTPS origin, environment credentials and no automatic retries. It reserves conservative text input/output charges within a provider-instance session cap before traffic. Unknown usage and ambiguous failures retain their reservation. Local cost remains unmeasured. A request cannot choose a new endpoint or smuggle a GPU mode into CPU-only permissions.

Auto execution is disabled throughout this alpha. Evidence import regrades retained outputs against versioned rubrics and hashes the dataset/policy/validator. A digest proves content identity, not that a workload is representative. Effective runtime identities and independently reviewed paired production evidence still need to be bound before a later Auto release can execute.

Normal runtime does not persist prompts or responses. Explicit evaluation retains them in a new private directory. Package/source release scripts use an explicit allowlist and never copy the research workspace as a whole. No models, credentials or CUDA DLLs are bundled.
