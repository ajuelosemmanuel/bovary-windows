# Windows CUDA component notices

## Gemma CUDA worker

The Windows CUDA launcher kit carries the Gemma `bovary-infer.exe` with its CUDA 13.3.1 toolkit terms at `setup/gemma-cuda/CUDA-LICENSE.txt`. Read those terms before using the CUDA worker. The NVIDIA portions may be used only with Bovary on systems with NVIDIA GPUs and are subject to the CUDA Toolkit EULA and applicable third-party notices. Keep the NVIDIA copyright and proprietary notices. The Bovary MIT license applies to the project-authored software.

The NVIDIA SDK license governs redistribution even when Bovary carries an executable with CUDA object code and obtains DLLs at setup. Sections 1.1.1–1.1.2 and Attachment A require redistribution as part of an application that adds material functionality, with SDK portions accessed only by that application and with consistent downstream terms. They also require application-user privacy, security and legal rights protections, enforcement of applicable downstream terms, and written notification to NVIDIA of known or suspected noncompliance. Section 1.2 includes restrictions on standalone distribution, reverse engineering, removing proprietary notices, endorsement and relicensing the SDK. The CUDA installation guide describes acceptance for NVIDIA's own installer. The reviewed SDK redistribution provisions prescribe downstream terms and enforcement and specify no particular click-through mechanism. [NVIDIA CUDA 13.3.1 EULA](https://docs.nvidia.com/cuda/archive/13.3.1/eula/index.html).

The Windows CUDA build selects `CUDA::cudart_static` through `GGML_STATIC=ON`. An earlier trial linked NVIDIA's separately named `cudart.lib`; the release worker was relinked against `cudart_static.lib` to match Attachment A. The release owner should approve the distribution terms and application-only access for the selected delivery channel before publishing. Section 2.5 provides NVIDIA's licensing contact at nvidia-compute-license-questions@nvidia.com. The exact CUDA 13.3.1 license copied by the kit builder, including Attachment B, has SHA-256 `088381bc2d891e719a2a9398645b00bb45f3b24231473a8283ac7e3e66b8a028`.

## Inkling developer preview

The kit uses the separate b12600 engine at `29b52d398b294509746ec0a3f28948a3107c0213`. Retain its own llama.cpp MIT notice, the applicable engine/CPU notices and the JSON for Modern C++ MIT notice from the pinned engine. The local preview executable imports `llama.dll`, `ggml.dll` and `ggml-base.dll`. Its upstream CUDA plugin imports `ggml-base.dll`, the cuBLAS DLL pair, and Windows/Microsoft runtime DLLs. The pinned upstream runtime ZIP contains that pair and `cudart64_13.dll`. The PE import check did not show a direct dynamic CUDART dependency for that plugin.

The preview builder uses the two hash-locked upstream CUDA 13.5 archives listed in [upstream.json](../previews/inkling/upstream.json). The upstream backend archive includes `LICENSE-LLVM-OpenMP`. The runtime archive contains three DLLs and supplies no separate license or notice file. Both archives are externally obtained. If the launcher selects these runtime DLLs for Gemma too, they remain CUDA 13.5 components, independent of the Gemma worker's 13.3.1 build dependency. The [CUDA 13.5 terms and notices](../licenses/NVIDIA-CUDA-13.5.txt) are reproduced from NVIDIA's hash-verified Windows CUDA Runtime 13.5.37 archive, with trailing whitespace removed. The archive's `cudart64_13.dll` is byte-identical to the copy in the pinned upstream runtime ZIP. The 13.5 license retains the SDK redistribution conditions and cuBLAS notices and updates Attachment B's LLVM notice. Read the applicable terms before obtaining or using these components. [NVIDIA CUDA EULA linked by the CUDA 13.5 documentation](https://docs.nvidia.com/cuda/eula/), [Inkling source notices](../previews/inkling/NOTICE.md).

Keep Inkling model weights and expert sidecars under the applicable model terms. Retain the original upstream GPU plugin and runtime archive hashes in the preview's lock.
